## Decision Log

### What we kept

- Local LiteLLM proxy as the default AI endpoint for the project
- `sk-local` as the local key for the proxy
- `auto-coder` as the stable default model alias
- `drop_params: true` to prevent unsupported parameter failures
- The startup documentation and PowerShell launcher as the repeatable setup path

### What we removed

- The assumption that the multi-provider fallback chain should be the primary operating path
- Unsupported request parameters that caused model-level rejection
- The need to re-discover the working setup each session

### What is the current stable default

- Base URL: `http://localhost:4000/v1`
- API key: `sk-local`
- Model alias: `auto-coder`
- Startup command: `python -m litellm.proxy.proxy_cli --config litellm_config.yaml --port 4000`
- App startup: `node server.js`
- Operational rule: treat external providers as optional fallbacks, not the standard path
